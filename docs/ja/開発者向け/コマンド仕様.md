# コマンド仕様

お立ち台Botがサーバーに登録するスラッシュコマンドの仕様です。
コマンド定義は `src/discord/commands/register.rs`、各ハンドラは `src/discord/commands/{admin,user}/` にあります。
ルーティングは `events::interaction::handle_command` が行います。

## 共通仕様

| 項目 | 内容 |
|---|---|
| スコープ | グローバル登録（`set_global_commands`）。すべてのギルドに同じコマンドが届く |
| 利用可能な場所 | サーバー内のみ。DMでの呼び出しは `guild_id` が `None` のため無視 |
| 言語 | `language::resolve_language(state, guild_id, interaction.locale)` で解決し、応答文言の i18n に使用 |
| 権限拒否時の応答 | `ephemeral` で `MessageKey::AdminPermissionDenied` のメッセージを返す |
| ハンドラ失敗時の応答 | `tracing::error!` でログ出力し、文字列 `"Error"` を返す |
| 管理者向け応答 | すべて `ephemeral` |

## 管理者コマンド一覧

権限要件：すべて `ADMINISTRATOR` または `MANAGE_GUILD` 権限を要求します（`check_admin_permission`）。

| コマンド | 用途 |
|---|---|
| [`/upload_guild_config`](#upload_guild_config) | ギルド全設定の YAML 一括アップロード |
| [`/download_guild_config`](#download_guild_config) | 現状のギルド全設定を YAML としてダウンロード |
| [`/list_question_presets`](#list_question_presets) | 質問プリセット一覧の閲覧 |
| [`/list_rooms`](#list_rooms) | 登録済み部屋の一覧閲覧 |

個別の `register_*` / `delete_*` / `set_*` 系コマンドは廃止し、YAML での全置換に統一されています。
YAML スキーマと運用ポリシーは [サーバー管理者向け ギルド設定YAML](../サーバー管理者向け/ギルド設定YAML.md) を参照してください。

## 利用者コマンド一覧

| コマンド | 用途 |
|---|---|
| [`/rent`](#rent) | レンタル申請の開始 |
| [`/help`](#help) | コマンドの説明を表示 |

## `/upload_guild_config`

ギルド全体の設定（チャンネル割り当て・質問プリセット・部屋・グループ・ルーティングルール）を YAML で一括反映します。
YAML はソース・オブ・トゥルース扱いで、添付ファイルに含まれない要素は削除されます（全置換セマンティクス）。

| 項目 | 内容 |
|---|---|
| 種別 | 管理者 |
| オプション | `file: Attachment`（必須）— YAML ファイル本体 |
| 主要呼び出し | `reqwest` で添付 URL を fetch → `facade::guild_config::parse()` → `with_guild_context()` 内で `facade::guild_config::apply()` |
| トランザクション | `db.guild` プール上の単一トランザクション。RLS は `app.current_guild_id` で強制 |
| 影響テーブル | `guild_channels`, `rental_question_presets`, `room_groups`, `rooms`, `rental_routing_rules`（`guilds.language` も任意で更新） |
| 削除カスケード | `rooms` 削除に伴い `rental_sessions` / `scheduled_tasks` が DB レベルで cascade |
| 強制 release | コミット後、`rental::routing::force_release_for_rooms` が in-memory 状態とタイムアウト Task を片付け、ホストへ DM |
| 応答 | `MessageKey::BotConfigUploadSuccess` ／ 強制 release が走った場合は `BotConfigUploadActiveSessionsReleased` を併記 |
| エラー応答 | YAML パース失敗 → `BotConfigUploadErrorYaml`／検証失敗 → `BotConfigUploadErrorValidation`（バリデーションメッセージを併記）／添付取得失敗 → `BotConfigUploadErrorAttachment` |

YAML の検証は `parse()` 内で完結し、検出したエラーをすべて配列で返します（fail-fast せず一度に提示）。

## `/download_guild_config`

現在の DB 状態を YAML にダンプし、Discord 添付として返します。
履歴は持たず常に最新スナップショットのみ。

| 項目 | 内容 |
|---|---|
| 種別 | 管理者 |
| オプション | なし |
| 主要呼び出し | `with_guild_context()` 内で `facade::guild_config::dump()` |
| 応答 | `attachment` として `guild_config.yaml` を返す |
| 空の場合 | 何も登録されていない場合でも、`version: 1` のみ含む空 YAML が返る（クライアント側で扱いやすくするため） |

ダンプ出力は `parse()` が必ず受理する保証があり、サニタイズ後にそのまま再アップロードできます（ラウンドトリップ可能）。

## `/list_question_presets`

登録済み質問プリセットの一覧をテキストで返します。

| 項目 | 内容 |
|---|---|
| 種別 | 管理者 |
| オプション | なし |
| 主要呼び出し | `facade::question_preset::list_presets()` |
| 応答 | 0 件 → `AdminQuestionPresetListEmpty`／1 件以上 → `AdminQuestionPresetListHeader` + プリセット名のリスト |

## `/list_rooms`

登録済み部屋の一覧を VC / TC / プリセット名つきで返します。

| 項目 | 内容 |
|---|---|
| 種別 | 管理者 |
| オプション | なし |
| 主要呼び出し | `facade::room::list_rooms()` + プリセット名解決 |
| 応答 | 0 件 → `AdminRoomListEmpty`／1 件以上 → `AdminRoomListHeader` + 各行 `AdminRoomListItem` |

## `/rent`

利用者がレンタル申請を開始します。

| 項目 | 内容 |
|---|---|
| 種別 | 利用者 |
| オプション | なし |
| 動作 | `rental::flow::start_rental(state, guild_id, user_id, voice_channel_id=None, lang)` を呼び出す |
| 応答 | `start_rental` の戻り値で分岐（下記） |

### 応答の分岐

| 戻り値 | 応答 |
|---|---|
| `AwaitingQuestions` | 利用目的入力モーダルを返す（`InteractionResponseType::Modal`） |
| `Assigned` | 割り当て完了メッセージを ephemeral で返す（`MessageKey::BotRentalAssigned`） |
| `AlreadyRenting` | ephemeral で `MessageKey::BotRentalAlreadyRenting` |
| `NoAvailableRooms` | ephemeral で `MessageKey::BotRentalNoRooms` |

このコマンドは VC 参加トリガーと違い、`voice_channel_id` を渡さないため**空き部屋の中から先頭順で1件**を割り当てます（`facade::room::find_available_room`）。

モーダル送信成功後は `rental::routing::post_purpose()` がフックされ、プリセットの `routing_key_index` が指す質問の回答で `rental_routing_rules` を引き、該当チャンネル（無ければフォールバック）へテンプレートをレンダリングして投稿します。投稿失敗は `tracing::warn!` でログに留め、レンタル成立処理は止めません。

## `/help`

Botのコマンド説明を表示します。

| 項目 | 内容 |
|---|---|
| 種別 | 利用者 |
| オプション | なし |
| 応答 | `MessageKey::HelpTitle` ／ `HelpUser` ／ `HelpAdmin` を結合した文字列 |

権限制御はないため、利用者にも管理者向けの一覧が表示されます（運用・公開ドキュメントに合わせる方針）。
