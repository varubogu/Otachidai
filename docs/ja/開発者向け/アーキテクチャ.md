# アーキテクチャ（開発者向け）

## システム概要

```
Discord Gateway
      │  WebSocket
      ▼
  Twilight        ← Discord APIクライアント（イベント受信・API送信）
      │
      ▼
ビジネスロジック   ← コマンド処理・レンタル状態管理・タイムアウト管理
      │
      ▼
   SeaORM         ← ORMレイヤー
      │
      ▼
  PostgreSQL       ← 永続化層（サーバー設定・部屋情報・レンタル状態）
```

## コンポーネント説明

### Twilight

Rustの非同期Discordライブラリ。Gateway経由でリアルタイムイベントを受信し、REST APIでメッセージ送信・チャンネル権限操作などを行います。

### ビジネスロジック

- **コマンドハンドラ** — スラッシュコマンドのルーティングと処理
- **レンタル状態マシン** — 申請→承認→利用中→解放の状態遷移を管理
- **タイムアウトマネージャ** — VC参加から10分のタイムアウト監視

### SeaORM + PostgreSQL

- サーバーごとの設定（言語、通報チャンネル、レンタルボタンチャンネル）
- 登録された部屋の一覧
- 現在のレンタル状態（誰がどの部屋を使用中か）

言語は `ja` と `en` に対応します。解決優先順位は Discord ユーザーの言語、`.env.app` の `APP_LANGUAGE`、`guild_master.guilds.language` の順です。`APP_LANGUAGE` が未設定で guild 設定もない場合の既定値は `ja` です。

## イベント処理フロー

### レンタル申請（VC参加の場合）

```
VC参加イベント
    │
    ├─ 既にレンタル中? → スキップ
    │
    ├─ 参加者のいないVC? → 申請フロー開始
    │       │
    │       ├─ 利用目的を尋ねるメッセージをVC付属チャットまたは登録済みテキストチャンネルへ送信
    │       │
    │       └─ タイムアウトタスク開始（10分）
    │               │
    │               ├─ 10分以内に入力完了 → タイムアウトキャンセル、部屋割り当て
    │               │
    │               ├─ 10分経過 → 運営に通知
    │               │
    │               └─ 10分以内にVC退出 → 申請キャンセル（通知なし）
    │
    └─ 参加者のいるVC → スキップ
```

### VC退出

```
VC退出イベント（部屋主が退出）
    │
    ├─ 他の参加者なし → 利用終了・部屋解放
    │
    └─ 他の参加者あり → 引き継ぎ確認メッセージ送信
            │
            ├─ 引き継ぎあり → 引き継ぎ者を新しい部屋主に設定
            │
            └─ 引き継ぎなし（タイムアウト or 拒否） → 部屋解放
```

## 開発環境のセットアップ

Dev Containerを使った環境構築を推奨します。

### VS Code + Dev Container

1. [Remote - Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers) 拡張をインストール
2. リポジトリをクローン
3. VS Codeでリポジトリを開き、「Reopen in Container」を選択
4. コンテナが自動的にビルドされ、Rust + PostgreSQL環境が起動します

### 環境変数

`.devcontainer/.env` を参照してください。本番用の `.env` は [Bot運用者向けセットアップ](../Bot運用者向け/セットアップ.md) を参照。
