# テーブル一覧

`guild_master` および `worker` スキーマ配下のテーブル仕様をまとめます。
カラム定義はマイグレーション（`migration/src/`）が、ORMモデルは `src/entities/`、クエリ層は `src/facade/` がそれぞれ正準ソースです。

## guild_master スキーマ

ドメインデータ。RLSが適用されます（[ロールとRLS.md](ロールとRLS.md) 参照）。

### `guild_master.guilds`

ギルドごとの基本設定。新規ギルド初登場時に `facade::guild_settings::ensure_guild` で自動INSERTされます。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `guild_id` | `BIGINT` | NOT NULL | — | PK。Discord guild id |
| `language` | `VARCHAR(5)` | NOT NULL | `'ja'` | 表示言語。`ja` または `en` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 作成時刻 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 更新時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `guild_id` |

書き換え経路: `ensure_guild`（自動）／ 言語変更コマンドは現状なし

---

### `guild_master.guild_channels`

ギルドの設定チャンネル。1ギルド × 1種別 × 1チャンネルの構造です。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | `SERIAL` | NOT NULL | — | PK |
| `guild_id` | `BIGINT` | NOT NULL | — | FK → `guilds.guild_id`（ON DELETE CASCADE） |
| `channel_id` | `BIGINT` | NOT NULL | — | Discord channel id |
| `channel_type` | `SMALLINT` | NOT NULL | — | 種別コード（下表） |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 作成時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `id` |
| FOREIGN KEY | `guild_id` → `guilds.guild_id` ON DELETE CASCADE |
| UNIQUE | `(guild_id, channel_type)` |

#### `channel_type` のコード値

定数は `src/entities/guild_channels.rs` で定義されています。

| 値 | 定数 | 用途 |
|---|---|---|
| `1` | `CHANNEL_TYPE_REPORT` | 通報先チャンネル（タイムアウト時の通知） |
| `2` | `CHANNEL_TYPE_RENTAL_BUTTON` | レンタルボタン常設チャンネル |

書き換え経路: `/register_report_channel`、`/register_rental_button_channel`

---

### `guild_master.rooms`

レンタル対象の部屋。テキストチャンネル単独・ボイスチャンネル単独・セットのいずれの形態も1テーブルで扱います。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | `SERIAL` | NOT NULL | — | PK |
| `guild_id` | `BIGINT` | NOT NULL | — | FK → `guilds.guild_id`（ON DELETE CASCADE） |
| `text_channel_id` | `BIGINT` | NULL可 | — | 紐付くテキストチャンネル |
| `voice_channel_id` | `BIGINT` | NULL可 | — | 紐付くボイスチャンネル |
| `is_available` | `BOOLEAN` | NOT NULL | `TRUE` | 空き状態フラグ |
| `question_preset_id` | `INT` | NULL可 | — | FK → `rental_question_presets.id`（ON DELETE SET NULL） |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 作成時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `id` |
| FOREIGN KEY | `guild_id` → `guilds.guild_id` ON DELETE CASCADE |
| FOREIGN KEY | `question_preset_id` → `rental_question_presets.id` ON DELETE SET NULL |
| UNIQUE | `(guild_id, text_channel_id)` |
| UNIQUE | `(guild_id, voice_channel_id)` |

`text_channel_id` と `voice_channel_id` の少なくとも一方が値を持つことはアプリケーション側で担保します（マイグレーション側の CHECK 制約はなし）。

書き換え経路: `/register_room`、`/delete_room`、`facade::room::set_room_availability`（レンタル開始/解放時に自動更新）

---

### `guild_master.rental_question_presets`

利用目的入力の質問プリセット。1〜10個の質問文を1行に持ちます。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | `SERIAL` | NOT NULL | — | PK |
| `guild_id` | `BIGINT` | NOT NULL | — | FK → `guilds.guild_id`（ON DELETE CASCADE） |
| `name` | `TEXT` | NOT NULL | — | プリセット名（ギルド内一意） |
| `question_1` 〜 `question_10` | `TEXT` | NULL可 | — | 質問文。空文字／空白のみは無効として扱う |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 作成時刻 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 更新時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `id` |
| FOREIGN KEY | `guild_id` → `guilds.guild_id` ON DELETE CASCADE |
| UNIQUE | `(guild_id, name)` |

`Model::questions()`（`src/entities/rental_question_presets.rs`）が空でない要素のみを抽出して `Vec<String>` を返します。

書き換え経路: `/register_question_preset`（同名で再実行すると上書き）

---

### `guild_master.rental_sessions`

レンタルセッションの永続状態。1セッション1行で、進行に伴って `state` を書き換えていきます。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | `SERIAL` | NOT NULL | — | PK |
| `guild_id` | `BIGINT` | NOT NULL | — | FK → `guilds.guild_id`（ON DELETE 指定なし） |
| `room_id` | `INT` | NOT NULL | — | FK → `rooms.id`（ON DELETE CASCADE） |
| `host_user_id` | `BIGINT` | NOT NULL | — | 部屋主のDiscord user id |
| `purpose` | `TEXT` | NULL可 | — | 利用目的入力結果 |
| `state` | `SMALLINT` | NOT NULL | `1` | 状態コード（下表） |
| `started_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 申請時刻 |
| `purpose_deadline` | `TIMESTAMPTZ` | NULL可 | — | 利用目的入力の期限（既定+10分） |
| `ended_at` | `TIMESTAMPTZ` | NULL可 | — | 解放時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `id` |
| FOREIGN KEY | `guild_id` → `guilds.guild_id` |
| FOREIGN KEY | `room_id` → `rooms.id` ON DELETE CASCADE |

#### `state` のコード値

定数は `src/entities/rental_sessions.rs`。状態遷移は [基本設計.md](../基本設計.md)／[アーキテクチャ.md](../アーキテクチャ.md) 参照。

| 値 | 定数 | 状態 |
|---|---|---|
| `1` | `STATE_AWAITING_PURPOSE` | 利用目的の入力待ち |
| `2` | `STATE_ACTIVE` | レンタル中 |
| `3` | `STATE_RELEASED` | 解放済み |
| `4` | `STATE_PENDING_HANDOFF` | 引き継ぎ確認中 |

書き換え経路: `facade::rental::*`（`create_session`／`set_purpose`／`release_session`／`transfer_host`／`set_pending_handoff`）

## worker スキーマ

タイマー・通知などのワーキング領域。RLSは**適用されていません**。`system`／`cleanup` ロールが横断アクセスする想定で、`guild_id` は論理的な分離キーとして持ちます。

### `worker.scheduled_tasks`

タイマー（利用目的タイムアウト）を永続化します。Bot再起動時の `restore_pending_timeouts` がここを再 spawn 元として使います。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | `SERIAL` | NOT NULL | — | PK |
| `guild_id` | `BIGINT` | NOT NULL | — | 対象ギルド（非正規化） |
| `task_type` | `SMALLINT` | NOT NULL | — | タスク種別（下表） |
| `rental_session_id` | `INT` | NULL可 | — | FK → `rental_sessions.id`（ON DELETE CASCADE） |
| `schedule_datetime` | `TIMESTAMPTZ` | NOT NULL | — | 発火時刻 |
| `processed` | `BOOLEAN` | NOT NULL | `FALSE` | 完了フラグ |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 作成時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `id` |
| FOREIGN KEY | `rental_session_id` → `rental_sessions.id` ON DELETE CASCADE |

#### `task_type` のコード値

| 値 | 定数 | 用途 |
|---|---|---|
| `1` | `TASK_TYPE_TIMEOUT_NOTIFICATION` | 利用目的入力タイムアウト |

引き継ぎタイムアウト（5分）はメモリ上のみで管理しており、現状ここには永続化されません。

書き換え経路: `facade::rental::create_session`（INSERT）／`mark_task_processed`（UPDATE）／タイムアウト発火時に `processed=true`

---

### `worker.notifications`

通報チャンネルへの送信履歴を残すためのテーブル。**現時点ではコード上で書き込み・読み込みされていない予約済みテーブル**です（マイグレーションで作成済み・将来の実装用）。

| カラム | 型 | NULL | 既定 | 説明 |
|---|---|---|---|---|
| `id` | `SERIAL` | NOT NULL | — | PK |
| `task_id` | `INT` | NOT NULL | — | FK → `scheduled_tasks.id`（ON DELETE CASCADE） |
| `guild_id` | `BIGINT` | NOT NULL | — | 対象ギルド（非正規化） |
| `schedule_datetime` | `TIMESTAMPTZ` | NOT NULL | — | 予定送信時刻 |
| `sent` | `BOOLEAN` | NOT NULL | `FALSE` | 送信済みフラグ |
| `sent_at` | `TIMESTAMPTZ` | NULL可 | — | 実送信時刻 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` | 作成時刻 |

| 制約 | 内容 |
|---|---|
| PRIMARY KEY | `id` |
| FOREIGN KEY | `task_id` → `scheduled_tasks.id` ON DELETE CASCADE |

書き換え経路: 現状なし（将来、通報失敗のリトライ管理等で使う想定）

## 命名規約

| 種別 | 規約 |
|---|---|
| 主キー | `id`（`SERIAL`）。例外として `guilds.guild_id` のみ Discord 由来のID自体をPKに使用 |
| 外部キー | 参照先の `<table>_id`（例: `room_id`、`question_preset_id`） |
| 時刻 | `*_at`（`TIMESTAMPTZ`）。アプリ側は UTC で書き込む（環境変数 `TZ=UTC` 前提） |
| 真偽値 | `is_*` または動詞過去分詞（`processed`、`sent`） |
| Discord 由来ID | `BIGINT`（i64）。`u64` のスノーフレークを `as i64` でキャストして格納 |
| ENUM 相当 | `SMALLINT` + Rust 側の `pub const` で対応定数を定義 |

`SMALLINT` をPostgreSQLの `ENUM` 型ではなく整数で表現しているのは、SeaORMでのマッピングをシンプルにするためです。コード値の追加はマイグレーション不要で、Rust側の定数追加のみで済みます。
