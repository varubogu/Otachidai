# 設定ファイル仕様

お立ち台Botが読み込む設定の一覧です。設定は3つのレイヤーに分かれています。

| レイヤー | 媒体 | 主担当 | スコープ |
|---|---|---|---|
| **環境変数** | `.env.app` | Bot運用者 | Bot プロセス全体 |
| **DB上のサーバー設定** | PostgreSQL（`guild_master.*`） | サーバー管理者 | 各サーバー（ギルド）単位 |
| **ロケールファイル** | `locales/{lang}/main.ftl` | 開発者 | Bot プロセス全体 |

このドキュメントは**ファイル形式**（環境変数とロケール）を中心に仕様化し、DB上の設定はスキーマと書き換え経路の参照のみ示します。
DB 上の設定はサーバー管理者が `/upload_guild_config` で YAML 一括反映します。YAML スキーマ自体の解説は [サーバー管理者向け ギルド設定YAML](../サーバー管理者向け/ギルド設定YAML.md) を参照してください。

---

## 環境変数（`.env.app`）

`src/config.rs::AppConfig::from_env` がプロセス起動時に読み込みます。`.env.app.example` をコピーして `.env.app` を作成してください。

### コア設定

| キー | 必須 | 既定値 | 用途 |
|---|---|---|---|
| `DISCORD_TOKEN` | 必須 | — | Discord Bot トークン |
| `BOT_ADMIN_SERVER_ID` | 必須（通常起動時） | — | Bot管理者専用サーバーのDiscord ID |
| `TZ` | 任意 | `UTC` | プロセスのタイムゾーン。`UTC` 推奨 |
| `RUST_LOG` | 任意 | `info` | `tracing` のフィルタ式（例: `info`, `debug`, `otachidai_bot=debug`） |
| `APP_LANGUAGE` | 任意 | なし | フォールバック言語。`ja` または `en`。未設定時はサーバー設定値、最終的に `ja` |

`APP_LANGUAGE` は `language::normalize_language` で正規化され、`ja` / `en` 以外を指定すると起動時にエラーになります。

### データベース接続情報

PostgreSQLには**4ロール**で別々に接続します。各ロールはRLSのバイパス可否や CRUD 範囲が異なります（詳細は [アーキテクチャ.md](アーキテクチャ.md) のDBロール表を参照）。

#### 共通

| キー | 必須 | 既定値 | 用途 |
|---|---|---|---|
| `DB_HOST` | 任意 | `localhost` | PostgreSQL ホスト |
| `DB_PORT` | 任意 | `5432` | ポート（数値で解釈できないと起動エラー） |
| `DB_NAME` | 任意 | `otachidai_bot_db` | データベース名 |

#### ロール別

| キー | 必須 | 用途 |
|---|---|---|
| `SYSTEM_DB_USER` / `SYSTEM_DB_PASSWORD` | 必須 | スケジューラ・バックグラウンド処理（BYPASSRLS） |
| `GUILD_DB_USER` / `GUILD_DB_PASSWORD` | 必須 | ギルド単位のコマンド実行（RLS適用） |
| `GLOBAL_DB_USER` / `GLOBAL_DB_PASSWORD` | 必須 | グローバル/マスターデータ更新（BYPASSRLS） |
| `ADMIN_DB_USER` / `ADMIN_DB_PASSWORD` | 必須 | マイグレーション実行（BYPASSRLS） |

#### マイグレーション専用

| キー | 必須 | 用途 |
|---|---|---|
| `DATABASE_URL` | マイグレーション時必須 | `sea-orm-cli`／migration バイナリが参照する admin ロール接続文字列 |

`.env.app.example` に `export DATABASE_URL=postgres://otachidai_bot_admin:...` の形でコメントアウトされています。
通常起動時には不要ですが、`/migrate` 等で参照されます。

### 必須・任意の判定

`config.rs::require_env` は環境変数が未設定の場合に `BotError::Env(<key>)` を返して起動を失敗させます。
任意のものは `std::env::var().unwrap_or_else(...)` でフォールバックします。

## DB上のサーバー固有設定

ギルド単位の設定は管理者が `/upload_guild_config` で YAML を投げて全置換します。Bot運用者が直接 SQL を編集する必要はありません。
スキーマは `guild_master` スキーマ配下です。

| テーブル | 内容 | 書き換え経路 |
|---|---|---|
| `guilds` | ギルドごとの言語などの基本設定 | `ensure_guild` で自動 INSERT。`language` は YAML の `guild.language` で更新 |
| `guild_channels` | 通報・レンタルボタン・部屋一覧・自動投稿フォールバックの各チャンネル | YAML の `channels.*` |
| `room_groups` | 部屋グループとそのテキストチャンネル | YAML の `room_groups[]` |
| `rooms` | レンタル対象の部屋 | YAML の `rooms[]` |
| `rental_question_presets` | 部屋ごとの質問プリセット | YAML の `question_presets[]` |
| `rental_routing_rules` | 自動投稿のルーティングルール | YAML の `routing_rules[]` |

全置換セマンティクス：`/upload_guild_config` は単一トランザクション内でこれらのテーブルを `DELETE` → `INSERT` し直します。YAML に含まれない要素は失われます。

### `guilds`

| カラム | 型 | 内容 |
|---|---|---|
| `guild_id` | `BIGINT` PK | Discord guild id |
| `language` | `TEXT` | 既定値 `ja`（`facade::guild_settings::DEFAULT_LANGUAGE`） |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 作成・更新時刻 |

`ensure_guild` がギルド初登場時に upsert します（`do_nothing` の `OnConflict`）。

### `guild_channels`

| カラム | 型 | 内容 |
|---|---|---|
| `id` | `SERIAL` PK | 内部ID |
| `guild_id` | `BIGINT` | Discord guild id |
| `channel_id` | `BIGINT` | Discord channel id |
| `channel_type` | `SMALLINT` | `1=通報` / `2=レンタルボタン` / `3=部屋一覧` / `4=利用目的自動投稿のフォールバック` |
| `message_id` | `BIGINT?` | 一覧表示用のメッセージID（`channel_type=3` でのみ利用） |
| `template` | `TEXT?` | `channel_type=4` のフォールバックで使うレンダリングテンプレート |
| `created_at` | `TIMESTAMPTZ` | 作成時刻 |

`(guild_id, channel_type)` で 1 行ずつ管理します（同種別チャンネルは1件のみ）。

### `room_groups`

| カラム | 型 | 内容 |
|---|---|---|
| `id` | `SERIAL` PK | 内部ID |
| `guild_id` | `BIGINT` | Discord guild id |
| `name` | `TEXT` | グループ名（ギルド内で一意） |
| `channel_id` | `BIGINT` | グループに対応するテキストチャンネル ID |
| `message_id` | `BIGINT?` | グループ別ステータスメッセージの ID |
| `created_at` | `TIMESTAMPTZ` | 作成時刻 |

### `rooms`

| カラム | 型 | 内容 |
|---|---|---|
| `id` | `SERIAL` PK | 内部ID |
| `guild_id` | `BIGINT` | Discord guild id |
| `text_channel_id` | `BIGINT?` | テキストチャンネルID（任意） |
| `voice_channel_id` | `BIGINT?` | ボイスチャンネルID（任意） |
| `is_available` | `BOOLEAN` | 空き状態フラグ。レンタル中は `false` |
| `question_preset_id` | `INT?` | 紐付ける `rental_question_presets.id` |
| `group_id` | `INT?` | 紐付ける `room_groups.id` |
| `created_at` | `TIMESTAMPTZ` | 作成時刻 |

YAML スキーマでは `voice_channel_id` が必須（部屋の識別子）。`rental_sessions` および `scheduled_tasks` は `rooms.id` に `ON DELETE CASCADE` で紐付くため、`/upload_guild_config` の全置換時は自動で消去されます。

### `rental_question_presets`

| カラム | 型 | 内容 |
|---|---|---|
| `id` | `SERIAL` PK | 内部ID |
| `guild_id` | `BIGINT` | Discord guild id |
| `name` | `TEXT` | プリセット名（ギルド内で一意） |
| `question_1` ～ `question_10` | `TEXT?` | 質問文。空文字や空白のみは無効として扱う |
| `answer_1` ～ `answer_10` | `TEXT?` | 選択肢（`,` で区切り、`,,` でリテラルカンマ） |
| `routing_key_index` | `SMALLINT?` | 自動投稿ルーティングに使う質問の 0-9 インデックス。最大 1 つ |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 作成・更新時刻 |

`routing_key_index` が指す質問は YAML 上では `routing_key: true` で表現されます。1 プリセットあたり最大 1 個までという制約は `facade::guild_config::validate()` で強制されます。

### `rental_routing_rules`

| カラム | 型 | 内容 |
|---|---|---|
| `id` | `SERIAL` PK | 内部ID |
| `guild_id` | `BIGINT` | Discord guild id |
| `preset_id` | `INT` | `rental_question_presets.id` への FK |
| `match_value` | `TEXT` | `routing_key` 質問の選択肢に対する一致値 |
| `channel_id` | `BIGINT` | マッチ時に投稿するチャンネル |
| `template` | `TEXT?` | テンプレート文字列（未指定なら i18n の `BotRentalPostDefaultTemplate`） |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 作成・更新時刻 |

`(preset_id, match_value)` でユニーク（YAML 検証時に重複拒否）。テンプレート構文は `src/rental/template.rs` の `parse()` が処理し、`{{ user }}` / `{{ room }}` / `{{ when }}` / `{{ preset }}` / `{{ q1 }}`〜`{{ q10 }}` / `{{ answer:質問名 }}` / `{{ answers }}` を受け付けます。

## ロケールファイル

UI文言はFluent形式で `locales/{lang}/main.ftl` に配置します。現在対応しているのは `ja` と `en` の2言語です。

### ファイル配置

```
locales/
├── ja/
│   └── main.ftl
└── en/
    └── main.ftl
```

`src/i18n/loader.rs` が起動時に両言語をロードし、`AppState.i18n` 経由で取り出します。

### キーの命名規則

`src/i18n/messages.rs` の `MessageKey` enum と `.ftl` のキーは1対1対応です。命名は kebab-case で、用途別の prefix を付けます。

| Prefix | 用途 |
|---|---|
| `bot-rental-*` | レンタルフローのユーザー向け文言（自動投稿のデフォルトテンプレートを含む） |
| `bot-handoff-*` | 引き継ぎフローの文言 |
| `bot-config-*` | YAML アップロード / ダウンロードの応答 |
| `admin-*` | 管理者コマンドの応答 |
| `status-*` | 部屋一覧メッセージ |
| `error-*` | エラー応答 |
| `help-*` | `/help` の各セクション |
| `rent-button-*` | レンタルボタンのラベル |

新規キーの追加は `/add-i18n` スキルから行うのが確実です。手動で書く場合は **両言語の `.ftl` と `messages.rs` の3箇所**を必ず揃えてください。

### プレースホルダ

Fluent の `{ $name }` 形式で動的値を埋めます。コード側は `FluentArgs` に `args.set("name", value)` で渡します。

```ftl
bot-rental-post-default-template = { $user } が部屋を借りました（{ $room }）{"\n"}{ $answers }
```

```rust
let mut args = FluentArgs::new();
args.set("user", format!("<@{user_id}>"));
args.set("room", room_mention);
args.set("answers", assembled_purpose);
state.i18n.get_with_args(lang, &MessageKey::BotRentalPostDefaultTemplate, Some(&args));
```

### 言語解決の優先順位

`language::resolve_language` は以下の順で言語を決定します。最初に有効な値が見つかった時点で確定します。

1. インタラクションの `interaction.locale` または VC イベントの `member.user.locale`（Discord ユーザーの言語）
2. 環境変数 `APP_LANGUAGE`
3. `guild_master.guilds.language`
4. `DEFAULT_LANGUAGE`（`ja`）

`ja-JP`、`en_GB` などの BCP-47 風表記は `normalize_language` で先頭の言語タグだけが見られます。
