# データベースマイグレーション

お立ち台BotはSeaORM Migrationを使ってスキーマを管理しています。マイグレーションファイルは `migration/src/` に配置し、`admin` DBロールで実行します。

## 新しいマイグレーションを作成する

### 1. ファイルを追加する

`migration/src/` にファイルを追加します。ファイル名の形式:

```
m<YYYYMMDD>_<6桁連番>_<snake_case説明>.rs
```

例: `m20240002_000001_add_foo_column.rs`

```rust
use sea_orm_migration::prelude::*;

pub struct Migration;

impl MigrationName for Migration {
    fn name(&self) -> &str {
        "m20240002_000001_add_foo_column"  // ファイル名（拡張子なし）と一致させる
    }
}

#[async_trait::async_trait]
impl MigrationTrait for Migration {
    async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        // DDLをここに記述
        manager
            .alter_table(/* ... */)
            .await
    }

    async fn down(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        // ロールバック処理
        Ok(())
    }
}
```

### 2. `migration/src/lib.rs` に登録する

`MigratorTrait::migrations()` の vec に追加:

```rust
mod m20240002_000001_add_foo_column;
// ...

vec![
    // 既存エントリ
    Box::new(m20240002_000001_add_foo_column::Migration),
]
```

## マイグレーションを実行する

### 開発環境

`.env.app` に `ADMIN_DB_*` の接続情報が正しく設定されていることを確認した上で実行します。

```bash
# 未適用のマイグレーションをすべて適用
cargo run --manifest-path migration/Cargo.toml -- up

# 1件だけ適用
cargo run --manifest-path migration/Cargo.toml -- up -n 1

# 1件ロールバック
cargo run --manifest-path migration/Cargo.toml -- down -n 1

# 適用済み一覧を確認
cargo run --manifest-path migration/Cargo.toml -- status
```

### Docker（本番・ステージング）

```bash
# 未適用のマイグレーションをすべて適用
docker compose --profile migration run --rm migration up

# 1件だけ適用
docker compose --profile migration run --rm migration up -n 1

# 1件ロールバック
docker compose --profile migration run --rm migration down -n 1

# 適用済み一覧を確認
docker compose --profile migration run --rm migration status
```

> **注意**: マイグレーションは `admin` DBロール（`ADMIN_DB_USER` / `ADMIN_DB_PASSWORD`）で実行されます。本番環境では Docker Compose の環境変数またはシークレットに正しい値が設定されていることを確認してください。
