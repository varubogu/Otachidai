# ギルド設定の YAML 一括管理 / 利用目的の自動投稿 仕様書

## 概要

ギルド（Discord サーバー）ごとの全設定を **単一の YAML ファイル** でアップロード / ダウンロードできるようにする。同時に、レンタル時の質問モーダル送信後に回答内容を所定のテキストチャンネルへ自動投稿する機能を追加し、その投稿先を **ルーティングキーフラグを付けた質問の回答** で振り分けられるようにする。

YAML はあくまで管理者と Bot 間のやり取り用フォーマットであり、設定の正は DB に保持する。アップロード時はパース → 検証 → DB へ反映し、ファイル自体は処理後に破棄する。

## スコープ

### YAML で扱う設定

| 種別 | DBエンティティ | 備考 |
|---|---|---|
| ギルド基本設定 | `guilds` | 言語（`ja` / `en`）等 |
| チャンネル設定 | `guild_channels` | report / rental_button / room_list / **rental_post_fallback (新)** |
| 質問プリセット | `rental_question_presets` | 各質問に **ルーティングキーフラグ** を付与可能 |
| 部屋グループ | `room_groups` | |
| 部屋 | `rooms` | プリセット参照 / グループ参照 / VC・テキストch ID |
| ルーティングルール | **`rental_routing_rules` (新)** | プリセット × ルーティングキー回答 → 投稿先ch |

### スコープ外

- ランタイム状態 (`rental_sessions`、`scheduled_tasks`、`notifications`) は YAML に含めない。
- 履歴・統計データの export / import。

## 廃止 / 維持するスラッシュコマンド

### 廃止（YAML 経由に一本化）

- `register_report_channel`, `register_rental_button_channel`, `register_room_list_channel`
- `register_question_preset`, `delete_question_preset`
- `register_room`, `delete_room`, `set_room_preset`, `set_room_group`
- `register_group`, `delete_group`

### 維持

- `list_question_presets`, `list_rooms`（軽量な状態確認用に存続）

### 新規

- `/upload_guild_config` — YAML ファイルを添付して全設定を置換適用
- `/download_guild_config` — 現在の全設定を **常に最新かつ完全な YAML** として ephemeral 添付で返却（差分出力は提供しない）

すべて管理者権限 (`ADMINISTRATOR` または `MANAGE_GUILD`) 必須、応答は ephemeral。

## YAML スキーマ

### 全体構造

```yaml
version: 1

guild:
  language: ja           # "ja" | "en"

channels:
  report: "123..."                 # 任意（未指定なら未設定／既存値削除）
  rental_button: "456..."
  room_list: "789..."
  rental_post_fallback:            # ルーティング不一致時の投稿先（任意）
    channel: "012..."
    template: |                    # 任意。未指定なら組み込みデフォルト
      {{user}} さんが {{room}} で利用を開始しました
      {{answers}}

question_presets:
  - name: "通常募集"
    questions:
      - text: "目的は？"
        answers: ["雑談", "作業", "イベント"]   # 省略時はテキスト入力
        routing_key: true                       # プリセット内で最大1つ
      - text: "募集人数"
        answers: ["1", "2", "3", "4"]
      - text: "備考"
        # answers 省略 → テキスト入力欄

room_groups:
  - name: "メインフロア"
  - name: "サブフロア"

rooms:
  - voice_channel_id: "111..."   # 部屋の同定子（DBスキーマと整合）
    text_channel_id: "222..."
    group: "メインフロア"          # room_groups[].name を参照
    question_preset: "通常募集"     # question_presets[].name を参照

routing_rules:
  - preset: "通常募集"               # question_presets[].name を参照
    rules:
      - when: "雑談"                # ルーティングキー質問の回答
        channel: "333..."
        template: |                # 任意。未指定なら組み込みデフォルト
          🎙 雑談部屋オープン！ host: {{user}} / room: {{room}}
          人数: {{answer:募集人数}}
          備考: {{answer:備考}}
      - when: "作業"
        channel: "444..."
        # template 省略 → 組み込みデフォルトを適用
```

### テンプレート構文

- プレースホルダ記法は **`{{ name }}` 形式**（Mustache/Handlebars 風）。波括弧の内側は前後の空白を許容（`{{user}}` も `{{ user }}` も同義）。
- リテラル `{{` / `}}` を出力したい場合は `\{{` / `\}}` でエスケープ。
- 利用可能変数：

| 変数 | 内容 |
|---|---|
| `{{user}}` | レンタル開始ユーザーのメンション (`<@...>`) |
| `{{room}}` | 部屋のテキストチャンネル mention（無ければ VC mention、それも無ければ部屋名フォールバック） |
| `{{when}}` | マッチしたルーティングキー回答（フォールバック時は空文字） |
| `{{preset}}` | 質問プリセット名 |
| `{{q1}}` 〜 `{{q10}}` | 各質問の回答（番号は YAML 上の questions 配列順、未回答 / 未定義の番号は空文字） |
| `{{answer:質問名}}` | 質問名（プリセット内の `text` と完全一致）で参照する回答。存在しなければ空文字 |
| `{{answers}}` | 全質問・全回答を組み立てた既存の purpose 文字列（複数行） |

- 未知のプレースホルダはバリデーション時にエラーとし、アップロードを拒否する。
  - 例: テンプレートに `{{q3}}` があるのにプリセットの質問が 2 個しかない → エラー
  - 例: `{{answer:存在しない質問名}}` → エラー
- テンプレート未指定時のデフォルトは、コードに埋め込んだ i18n 既定テンプレートを適用（後述 i18n キー参照）。

### 共通バリデーション

- `version` は 1 固定。
- すべてのチャンネル ID / VC ID は 17〜20 桁の数値文字列。
- 同一スコープ内の名前 (`question_presets[].name`、`room_groups[].name`) は重複不可。`rooms` は `voice_channel_id` の重複不可（DB 側の UNIQUE 制約と整合）。
- 参照（`rooms[].group`、`rooms[].question_preset`、`routing_rules[].preset`）は同一 YAML 内に存在しなければエラー。
- ルーティングキーがドロップダウンの質問なら、`routing_rules[].rules[].when` はその選択肢に含まれていること（タイポ防止）。テキスト質問の場合は任意文字列を許容。
- 各プリセット内で `routing_key: true` は最大 1 個（複数あればエラー）。プリセットにルーティングルールがあるのにルーティングキー指定がなければエラー。
- `rooms[].question_preset` の質問は最大 10 個（Discord モーダル仕様＋現状の DB スキーマ）。
- テンプレートに含まれる全プレースホルダがプリセット定義に対して有効であること（未知変数があればエラー）。

### 適用セマンティクス（置換 / Force）

- アップロードされた YAML が **ギルド設定全体のソース・オブ・トゥルース** となる。YAML に存在しないエンティティは削除される。
- 削除対象に **アクティブなレンタルセッションを持つ部屋** が含まれる場合：
  - 該当セッションは強制的に release される（DB ステート=Released、ルーム availability 復旧、in-memory `rental_states` エントリ削除、タイムアウトタスク abort、`scheduled_tasks` を processed 化）。
  - ホストには通知メッセージを送信（i18n: `bot-rental-force-released`）。
- 削除順序：`rental_routing_rules` → `rooms` → `room_groups` → `rental_question_presets` → `guild_channels`（FK 依存順）。
- 全処理を単一 DB トランザクションで実行し、途中失敗時は完全ロールバック。in-memory 状態の変更も最後のコミット成功後にまとめて反映。

## データモデル変更

### 新規テーブル `guild_master.rental_routing_rules`

| カラム | 型 | 備考 |
|---|---|---|
| `id` | serial PK | |
| `guild_id` | bigint NOT NULL | RLS 対象 |
| `preset_id` | int NOT NULL FK → `rental_question_presets.id` ON DELETE CASCADE | |
| `match_value` | text NOT NULL | ルーティングキー質問の期待値 |
| `channel_id` | bigint NOT NULL | 投稿先 Discord テキストチャンネル |
| `template` | text NULL | 投稿テンプレート（NULL = 既定テンプレート使用） |
| `created_at` | timestamptz NOT NULL DEFAULT now() | |
| `updated_at` | timestamptz NOT NULL DEFAULT now() | |

- UNIQUE: `(guild_id, preset_id, match_value)`
- INDEX: `(guild_id, preset_id)`
- RLS: 既存パターン (`current_setting('app.current_guild_id')`) を踏襲

### `guild_channels` の拡張

- 追加カラム: `template` text NULL — フォールバック投稿時のテンプレート保持に使用。`channel_type = CHANNEL_TYPE_RENTAL_POST_FALLBACK` 行でのみ意味を持ち、他の type 行では NULL を保つ運用とする（カラム自体は共通化）。

### `rental_question_presets` の拡張

各質問にルーティングキー有無を保持する。プリセット内で最大 1 個。

- 追加カラム: `routing_key_index` smallint NULL — 0〜9。NULL = ルーティングキー未指定
- なぜカラム追加 / フラグ列挙でないか：質問本体は 1〜10 のカラムで保持されている既存スキーマと整合させ、ルーティングキーは「どの番号の質問か」を整数 1 個で表す方が後方互換性を維持しやすい。

### `guild_channels` への新 type

- `CHANNEL_TYPE_RENTAL_POST_FALLBACK = 4`（テーブル変更不要、定数追加と const 配布のみ）

## 投稿フロー（`submit_purpose` のフック）

`src/rental/flow.rs::submit_purpose` 内、`set_purpose` の DB 書き込みが成功した直後に以下を実行する：

1. セッションの `room.question_preset_id` を取得。未設定 → 投稿スキップ。
2. プリセットの `routing_key_index` を取得。
   - 未指定 → ルーティング判定は行わず、フォールバックチャンネルがあればそこへ投稿。
3. ルーティングキー質問の回答文字列を `dropdown_answers` / `text_answers` から取り出す。
4. `rental_routing_rules` から `(guild_id, preset_id, match_value)` で検索。
5. 一致したルールがあれば `(channel_id, template)` を採用、なければフォールバック行の `(channel_id, template)` を採用。両方未設定なら投稿スキップ + `tracing::warn!`。
6. `template` が NULL の場合は組み込みデフォルト（i18n の `bot-rental-post-default-template`）を採用。
7. テンプレートをレンダリングする。展開変数は **投稿フロー側で構築** する：
   - `user` / `room` / `preset` / `when`
   - `q1`〜`qN`（プリセットの実質問数まで。未定義番号の埋め込みはバリデーションで弾かれているのでここでは発生しない）
   - `answer:<質問名>` ベースの解決テーブル
   - `answers`（既存の `assemble_purpose_from_parts` 結果を再利用）
8. `http.create_message().content(rendered).await` が失敗してもレンタル成立処理は止めず、`tracing::warn!` のみ。

新規モジュール案：
- `src/rental/routing.rs` — マッチング判定 + 投稿
- `src/rental/template.rs` — テンプレートのパース / バリデーション / レンダリング（Mustache 風 `{{ name }}`）
- `src/facade/routing.rs` — `rental_routing_rules` CRUD
- `src/facade/guild_config.rs` — YAML 適用 / ダンプの全体オーケストレーション

### テンプレート処理方針

- テンプレートエンジンは外部クレートに依存せず、本機能用に **最小限の自前パーサ** を実装する（プレースホルダは `{{ name }}` 限定で条件分岐や反復は持たない）。
  - 理由: handlebars / tinytemplate 等は機能過剰で攻撃面が広がる。本機能の変数は固定セットなので 100 行以下で書ける見込み。
- パース結果は `Vec<Segment>`（`Segment::Literal(String)` / `Segment::Var(VarKey)` の列）に保持する。
- バリデーションは **アップロード時に 1 度** 実行し、テンプレート文字列をそのまま DB に保存する（レンダリング時に再パース）。
  - DB に AST を保存しないのは、ダンプ時に「人間が編集した原文」を返したいため。
- レンダリング失敗時（理論上は発生しないが安全策として）は `tracing::error!` + 投稿スキップ。

## 追加する i18n キー

設定系：
- `bot-config-upload-success`
- `bot-config-upload-error-yaml-parse`
- `bot-config-upload-error-validation`（バリデーションエラーは行/フィールド情報を含む詳細メッセージを別途構築）

- `bot-config-download-empty`

投稿系：
- `bot-rental-post-default-template`（引数: `user`, `room`, `answers`。テンプレート未指定時に適用される既定テンプレート）
- `bot-rental-force-released`（強制 release されたホストへの通知）

設定エラー系：
- `bot-config-upload-error-template-unknown-var`（テンプレートに未知変数が含まれる旨）
- `bot-config-upload-error-template-syntax`（`{{` のアンバランス等のパースエラー）

`/add-i18n` で ja / en を同時追加する。

## 確定済み事項

- `/download_guild_config` は常に最新の完全な YAML を返す（差分出力は提供しない）。
- ルーティングキー未指定のプリセットは、ルーティング判定を行わずフォールバックチャンネルへ投稿する。
- 投稿本文はテンプレート機構で構築し、回答内容を本文に反映する。テンプレート未指定時は組み込みデフォルトを適用。
- 既存ギルドの移行は「リリース後に `/download_guild_config` で取得 → 必要なら編集 → `/upload_guild_config` で投入」で運用する。
